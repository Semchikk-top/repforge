# Тренировки (PWA): клиент + сервер синхронизации

Личный дневник тренировок. Клиент работает полностью офлайн (IndexedDB), сервер на ПК собирает данные
со всех твоих устройств. Один пользователь, несколько устройств.

## Установка на ПК (Omarchy)

```bash
bash deploy/install.sh
```

Скрипт соберёт клиент, создаст `.venv`, поставит и запустит сервис `workout` (127.0.0.1:8000).
Данные лежат в `~/workout-data/` (база и ежедневные копии, хранятся 14 штук).

## HTTPS и доступ с телефона

PWA и Service Worker работают только по HTTPS. Самый простой путь — Tailscale:

```bash
sudo tailscale serve --bg 8000
tailscale serve status        # покажет адрес https://<имя-пк>.<tailnet>.ts.net
```

Tailscale должен быть установлен и на телефоне. Тогда синхронизация работает и дома, и вне дома.

## Подключение устройств

Устройства подключаются по одноразовому коду (10 минут). Есть три способа, все ведут в один и тот же процесс сопряжения.

1. **Первое устройство (сам ПК).** `bash deploy/install.sh` в конце печатает ссылку: открой её в браузере на ПК.
   Вручную: `python -m server pair` (адрес определится сам; можно указать `--url`).
2. **Телефон рядом, по QR.** В приложении на ПК: Профиль → Настройки → Синхронизация → **«Подключить телефон рядом»**.
   Сервер сам выбирает лучший адрес (Tailscale с HTTPS, затем локальная сеть), показывает QR и ссылку.
   Наведи камеру телефона, открой ссылку, и устройство подключится. Окно на ПК покажет «Подключено».
3. **Запрос с телефона.** Открой на телефоне адрес сервера, Профиль → Настройки → Синхронизация → **«Запросить подключение к ПК»**.
   Телефон покажет PIN из 4 цифр, на ПК появится окно с таким же PIN: сверь и нажми «Разрешить».
   Без подтверждения код не выдаётся никому, поэтому посторонний в сети подключиться не сможет.

Установленное приложение и браузер могут хранить данные раздельно. Если после установки подключения не видно,
подключись ещё раз одним из способов выше.

### Автопоиск в локальной сети (mDNS)

Сервер умеет публиковать себя в локальной сети как `_workout._tcp` и получать имя `<хост>.local`:

```bash
# в ~/workout-data/.env:  WORKOUT_HOST=0.0.0.0  и  WORKOUT_MDNS=1,  затем: systemctl --user restart workout
python -m server discover     # проверка: показывает найденные серверы
```

Что важно знать:
- **Из PWA найти такой сервис нельзя**: у браузеров нет API для mDNS. Поэтому телефон сам «увидеть» ПК не сможет;
  вместо этого адрес передаётся через QR или запрос с подтверждением (способы 2 и 3).
- По **обычному HTTP** в локальной сети приложение подключится, но **не установится как PWA**, а Wake Lock, уведомления
  и офлайн-кэш в браузере не заработают (всё это требует HTTPS). Токены и данные по HTTP идут открытым текстом.
  Для полноценной работы используй Tailscale: между устройствами в одной сети он тоже ходит напрямую.
- По умолчанию сервер слушает только `127.0.0.1`, и mDNS выключен.

## Ассистент

Ассистент живёт на сервере: он читает твой журнал (только чтение), общается с моделью и отдаёт ответ потоком.
Кнопка ✦ открывает чат; на экране тренировки такая же кнопка в шапке.

### Справочник (1.4.0)

На теоретические вопросы («зачем жим лёжа», «какие мышцы в тяге», «почему важен отдых») ассистент отвечает по справочнику из `content/`, а не по общим знаниям модели: для этого у него есть инструменты `get_exercise_card` и `get_principle`. Он видит только `published` и ссылается на источник. Если в справочнике ничего нет, он так и говорит («В справочнике этого нет») и помечает общий ответ как непроверенный. О лекарствах, добавках и диагнозах не рассуждает. Чтобы посмотреть, как он отвечает по черновикам, поставь `REPFORGE_CONTENT_PREVIEW=1` в `~/workout-data/.env` (ответы помечаются как черновик). Список названий для поиска (`content/exercise_names.json`) создаёт `npm run content:build` из `seed.ts`.

### Подключение модели

**Профиль → Настройки → Ассистент → «Настроить подключение»** (править файлы не нужно). Три способа:

- **Облако.** Выбери провайдера (Anthropic или любой OpenAI-совместимый: OpenAI, OpenRouter…), введи API-ключ и модель.
  Ключ хранится на ПК и в приложение обратно не возвращается (видны только последние 4 символа). Если сменить адрес
  провайдера, сохранённый ключ удаляется: он не должен уйти на другой адрес.
- **Ollama.** Адрес по умолчанию `http://127.0.0.1:11434/v1`. Модель можно не указывать: возьмётся первая установленная
  (`ollama pull qwen2.5:7b`). Если модель не умеет инструменты, ассистент ответит без доступа к данным.
- **Агент.** Локальный агент на ПК (например, на Omarchy): любой сервис с OpenAI-совместимым API
  (`/v1/chat/completions` и `/v1/models`): llama.cpp, LM Studio, vLLM или свой агент. Нужны адрес (например,
  `http://127.0.0.1:8080/v1`) и, если агент его требует, токен. Адрес должен вести на этот ПК или в домашнюю сеть.

Кнопка «Сохранить и проверить» ничего не тратит: она запрашивает у провайдера список моделей и показывает их, чтобы выбрать одну нажатием.
Переключатель «Облако / Ollama / Агент» в настройках выбирает, кто отвечает. Телефон по умолчанию использует облако, ПК — Ollama.
Настройки из приложения главнее переменных окружения (`ANTHROPIC_API_KEY`, `ASSISTANT_*` в `.env`), которые остаются запасным вариантом.

- **Что он умеет:** смотреть последние тренировки, историю упражнения, рекорды, недельные сводки, план, справочник;
  предлагать тренировку. Предложение появляется карточкой, и в календарь оно попадёт только после твоего нажатия.
- **Приватность:** в облачном режиме нужные записи из дневника уходят провайдеру модели вместе с вопросом.
  Ollama и агент ничего не отправляют наружу. История чата хранится только на устройстве.
- Перед каждым вопросом приложение синхронизируется, чтобы ассистент видел свежие данные.

## Озвучка Fish Speech (1.6.0, экспериментально)

Готовые подсказки можно озвучивать своим голосом через Fish Speech на ПК: вкладки «Сервер» (подключение) и «Звук» (голоса, подготовка, студия) в настройках. Устройство и статус проверок: [VOICE.md](VOICE.md).

Функция экспериментальная: обмен с настоящим Fish, качество русской озвучки на GTX 1050 и воспроизведение при погашенном экране на телефоне ещё не проверены. По умолчанию озвучка выключена.

## Бег, ходьба и велосипед

Упражнения «Бег», «Ходьба» и «Велосипед» (группа «Кардио») работают без подходов: вместо кг и повторений у них дистанция, время и темп.
Свои кардио-упражнения создаются так же, как обычные, с группой «Кардио»; вид спорта определяется по названию.

- **Запись GPS.** В тренировке у кардио-упражнения кнопка «Начать запись GPS»: крупные дистанция, время, текущий и средний темп
  (для велосипеда скорость), километровые отрезки, набор высоты, пауза. Шум GPS отфильтрован: отбрасываются неточные
  точки, скачки и дрожание на месте. Маршрут рисуется линией на экране без подложки карты: он работает офлайн и ничего не уходит наружу.
- **Если запись прервалась** (страница перезагрузилась, вкладку закрыли), при возврате в тренировку приложение предложит продолжить,
  сохранить как есть или отбросить.
- **Вручную.** «Ввести вручную» для беговой дорожки и тренировок без GPS.
- **Аналитика.** Раздел «Бег и ходьба»: километры за 30 дней, средний темп, километры по неделям, лучшие 1, 5 и 10 км (по записанным
  маршрутам), самая длинная пробежка. Ассистент видит только итоги (инструмент `get_cardio_history`), координаты ему не передаются.
- **Приватность.** Маршруты хранятся на устройстве и синхронизируются только с твоим сервером на ПК. Карта-подложка и любые внешние сервисы
  включаются только твоими нажатиями (см. «Уличный режим» ниже); «В помещении» и «Просто запись» ничего наружу не отправляют.

### Уличный режим: карта, маршрут, голос (1.2.0)

В кардио сначала выбирается **«Где тренировка?»**: «На улице» или «В помещении» (последний выбор подсказывается, но сам не применяется).
«В помещении»: только ручной ввод. «На улице» → «Начать запись GPS» открывает подготовку:

- **Просто запись**: как раньше, схематичная линия без карты и без сети.
- **Карта** — только после кнопки «Показать карту» (MapLibre + OpenFreeMap). Не загрузилась (нет сети, WebGL, сервис недоступен): запись идёт дальше, маршрут рисуется схемой.
- **Маршрут**: точки нажатием на карту или поиском адреса («Найти»), до 10 точек; пешком для бега и ходьбы, велосипедный профиль для велосипеда.
  При построении сервису маршрутов уходят координаты точек; при поиске — введённый текст. Больше ничего.
- **Навигация** по готовому маршруту работает без сети: сохранённая линия и GPS. Сход с маршрута (устойчивый, с учётом точности GPS) →
  автоматическое перестроение не чаще раза в 30 секунд; без сети остаются сохранённый маршрут и подсказка вернуться.
- **Голос** (по умолчанию выключен, включается в подготовке или в настройках): «Голос навигации» (повороты за 120/40/15 м пешком и 300/100/30 м на
  велосипеде, сход, финиш) и «Тренировочные подсказки» (половина дистанции, смена пульсовой зоны при живом датчике и заданном максимальном пульсе, темп при заданной цели).
  Километры озвучивает прежняя настройка. Навигация приоритетнее тренировочных фраз. На экране записи есть «Выключить голос».
  В приложении для телефона речь идёт системным синтезатором и слышна при погашенном экране; в браузере она может замолкать.

**Какие внешние сервисы и адреса** (все бесплатные, без ключей; заменяются своими копиями):

| Что | По умолчанию | Переменная сборки | Сервер (CSP) |
|---|---|---|---|
| Стиль и тайлы карты | OpenFreeMap (`tiles.openfreemap.org`) | `VITE_MAP_STYLE_LIGHT`, `VITE_MAP_STYLE_DARK` | `WORKOUT_MAP_ORIGINS` |
| Маршруты | Valhalla FOSSGIS (`valhalla1.openstreetmap.de`) | `VITE_ROUTER_URL` | то же |
| Поиск адреса | Nominatim (`nominatim.openstreetmap.org`) | `VITE_GEOCODER_URL` | то же |

`WORKOUT_MAP_ORIGINS` — список источников через запятую (заменяет умолчание целиком; пустая строка отключает внешние запросы карты полностью);
`npm run build:public` берёт те же адреса из `VITE_*`. Разрешаются только точные `https://хост[:порт]`, без `*`.

**Ограничения публичных сервисов.** Публичный Valhalla и Nominatim рассчитаны на разработку и умеренное использование: без гарантий доступности,
с ограничением частоты (поиск адреса в приложении не чаще 1 запроса в секунду и кэшируется). Nominatim может отказать запросам без указания источника
(приложение не отправляет Referer): тогда выбирай точку на карте. Для регулярного использования подними свои Valhalla/Nominatim и тайлы и
подставь адреса переменными выше. Атрибуция «© участники OpenStreetMap» и OpenFreeMap показана на карте.

**Android.** `npm run cap:sync` добавляет в манифест `queries` для `TTS_SERVICE`, без этого системный синтезатор речи не виден приложению.

**Важно знать**
- Браузер даёт доступ к GPS только по **защищённому адресу**: через Tailscale (`tailscale serve`, https) или на самом ПК (localhost).
  Через `http://192.168…` в домашней сети запись GPS недоступна, но ручной ввод работает.
- PWA пишет маршрут, **только пока экран включён и приложение открыто**: в фоне iOS и Android усыпляют страницу. Во время записи экран не гаснет.
  Если экран всё же выключался, приложение предупредит, что часть пути могла не записаться. Для долгих пробежек с телефоном в кармане
  надёжнее потом сделать нативную обёртку.
- Высота с GPS приблизительная, набор высоты считается с порогом 3 м.

## Версия 1.0: «что делать сегодня» и слияние всех таблиц

- **Главный экран.** Наверху календаря карточка «Сегодня» с одним главным действием: продолжить идущую тренировку, начать запланированную, перенести пропущенную на сегодня, отдохнуть или (если плана нет) повторить следующую по твоему ритму. Новичку она показывает три шага и ведёт к подбору стартовой программы.
- **Слияние.** По полям теперь сливаются упражнения, шаблоны, программы, замеры, чек-ины и настройки игры, а не только тренировки (подробности в «Как устроена синхронизация»).
- **Исправлено.** Дата получения достижения больше не показывается как 1 января 1970.

## Версия 0.11 (альфа): надёжность синхронизации

- **Версии.** Приложение и сервер сверяют версию протокола синхронизации, а сервер ещё и схему базы. Если одна из сторон устарела, в приложении появляется понятное сообщение, что обновить. Обновляй сервер вместе с клиентом: `git pull` и `bash deploy/install.sh`.
- **Часы.** Если часы устройства расходятся с сервером больше чем на две минуты, наверху появляется плашка: побеждает запись с большим временем правки, и сбитые часы могут затирать чужие изменения.
- **Слияние тренировок.** Правки одной тренировки на двух устройствах теперь сливаются по подходам, а не побеждает целая запись (подробности в разделе «Как устроена синхронизация»).
- **Диагностика.** Настройки → «Диагностика» появляется после достижения «Разработчик» (семь нажатий на версию внизу настроек). Там версии, состояние синхронизации, сведения сервера и журнал ошибок; «Скопировать отчёт» не включает токены и содержимое тренировок.
- **Быстрее запуск.** Редкие экраны грузятся по требованию: главный файл на четверть меньше.

## Версия 0.6 (альфа): геймификация

- **Опыт и монеты.** За каждую завершённую тренировку: 40 XP за сам факт + 1 XP за каждые 40 кг объёма (вес × повторы рабочих подходов) + XP за километры (бег 40, ходьба 15, велосипед 10 за км). Монет в четыре раза меньше, чем опыта. Подход без веса (подтягивания) считается как 30 кг на повтор. Разминка не считается. Награда за тренировку никогда не уменьшается, даже если потом поправить подходы.
- **Уровни** 1–100, звание зависит от уровня (Новичок … Титан). Старые тренировки засчитываются сами при первом запуске.
- **Достижения** (Профиль → Награды): тренировки, серии недель, силовые (жим 100 кг — «Выдающийся»), объём, кардио и секретные, условия которых скрыты, пока не получены. За каждое дают монеты и столько же опыта.
- **Магазин** (Профиль → Магазин): аватары (есть анимированные, тапните по аватару в профиле), рамки, фоны шапки, цвет всего приложения и звания. Предмет можно примерить до покупки. Часть предметов выдаётся только за достижения.
- **Профиль** — отдельная вкладка нижнего меню (на месте «Настроек», на кнопке виден ваш аватар). Внутри: шапка с уровнем и монетами, вкладки «Обзор / Награды / Магазин / Друзья» и кнопка настроек справа вверху. Раздел «Профиль и друзья» перенесён из настроек на вкладку «Друзья».
- **Очередь изменений.** Правки одной записи схлопываются в одну строку очереди: вес 50 → 60 кг четырьмя нажатиями «+2,5» даёт одно изменение, а не четыре, и счётчик на вкладке «Профиль» растёт только по числу изменённых записей (тренировка, упражнение, шаблон — одна запись). На сервер и так уходит итоговое состояние записи, а не шаги правки. Очередь, накопленная старой версией, чистится один раз при запуске.
- **Синхронизация.** Опыт и монеты не хранятся числом: они считаются из журнала записей (новая таблица `game`), поэтому телефон и ПК не затирают друг другу баланс. Если потратить монеты на двух устройствах без связи, баланс после синхронизации может уйти в минус до следующих тренировок. **Сервер нужно обновить вместе с клиентом:** старый сервер отклонит таблицу `game`.

## Версия 0.3 (альфа): что нового

- **RPE и подсказка прогрессии.** Нажми на номер подхода и отметь усилие (RPE 6–10). Подсказка «Идея на сегодня» теперь объясняет причину:
  на пределе (RPE 9,5+) не прибавлять; легко (RPE ≤ 7) прибавить сразу два шага или два повтора; после перерыва больше трёх недель начать с ~90% веса;
  если повторы падают две тренировки подряд при том же весе, сделать разгрузку −10%. Кнопка «Спросить ассистента» подставляет вопрос про это упражнение в чат.
- **Программы.** Тренировка → «Программы тренировок»: выбери дни недели, шаблон на каждый день и число недель, затем «Назначить в календарь».
  Прошедшие даты пропускаются, повторное нажатие дубликатов не создаёт. Для программы нужны шаблоны (сохрани завершённую тренировку как шаблон).

## Справочное содержимое: «Зачем это» (1.3.0)

Кнопка ⓘ у упражнения открывает короткую карточку (суть, мышцы, техника, ошибки, замена, источник). Всё лежит в сборке, работает без сети и не синхронизируется.

```
content/muscles.json            справочник мышц (id, название, группа приложения, сторона тела для будущей карты)
content/sources.json            реестр источников: название, автор, ссылка https, лицензия, дата получения
content/exercises/seed-NNN.json одна карточка на стартовое упражнение (NNN — id из src/domain/seed.ts)
content/principles/<slug>.json  короткие заметки-принципы для «Почему так» (1.4.0): те же статусы и проверки
```

Принципы: образовательная информация, а не медицинская рекомендация; в приложение попадает только `published`, и статус ставит человек; у каждой карточки есть источник с разрешающей лицензией; никаких наград за знания.

С 1.6.0 опубликованы 32 карточки и 12 принципов. Силовые карточки опираются на OpenStax (лицензия книги `CC-BY-4.0`; противоречивые условия на сайте и риск зафиксированы в `CHANGELOG.md`), новые принципы и кардио — на Wikipedia (`CC-BY-SA-4.0`) и HHS Physical Activity Guidelines (`Public-Domain`). Курс «Как растут мышцы» остаётся черновиком, поэтому раздел «Знания» пока скрыт.

```bash
npm run content:check                          # проверить всё в content/
npm run content:status -- seed-001 reviewed    # draft → reviewed → published (даты ставятся автоматически)
npm run content:build                          # собрать в src/content/bundle.generated.json только published
npm run content:preview                        # то же с черновиками: только посмотреть на своём устройстве
CONTENT_PREVIEW=1 npm run build:native         # сборка для телефона с черновиками (в релиз не отправлять)
```

Для `published` у карточки нужны источник (мышцы и функция) и `techniqueReview` (кто и когда проверил технику и ошибки: `{ "by": "тренер", "at": "2026-11-12" }`).

Новая карточка: скопировать готовую, поменять `id` и имя файла, заполнить поля, добавить источник в `sources.json`, прогнать `content:check`. Лимиты длины и запрещённые темы проверяет валидатор (`src/content/validate.ts`). Чтобы не отправить в магазин сборку с черновиками, перед релизом: `npm run content:build && npm run content:check -- --release`.

### Конвейер знаний (1.5.0)

Помогает готовить новые карточки и принципы быстрее, но ничего не публикует: модель предлагает, скрипт проверяет, решает человек. Команды запускаются на ПК из каталога проекта (`PYTHONPATH=.`, если запускаешь не через сервис). Нужна локальная модель в Ollama (`ASSISTANT_LOCAL_MODEL`, либо первая установленная).

1. Сохрани главу открытого источника в файл (`.txt`, `.md` или страницу `.html`) и добавь:
   `python -m server content source add --id openstax-ap2e-ch11 --title "…" --author "…" --url https://… --license CC-BY-4.0 --file глава.html`
   Лицензия вне списка в `content/rules.json` отклонится. Снимок текста ложится в `content/snapshots/`.
2. Черновик: `python -m server content draft card seed-001 --source openstax-ap2e-ch11 --start 0 --end 9000` (для английского источника добавь `--lang en`).
3. Просмотр: `python -m server content review card seed-001`. ✗ у цитаты значит, что её нет в источнике. Недостающие поля остаются пустыми.
4. Правки руками в `content/drafts/card-seed-001.json`, затем `content check card seed-001`. Для перевода: `content review card seed-001 --terms-ok` после сверки терминов.
5. `content accept card seed-001 [--replace]` кладёт карточку в `content/exercises/` со статусом `draft`. Дальше обычный путь: `npm run content:check`, проверка человеком, `npm run content:status -- seed-001 reviewed`.

Золотой набор перед массовой работой: заполни `content/golden/golden.json` (список `{kind, target, source, start, end, lang}` для 5 проверенных карточек), `content golden run`, разметь лист `[x]/[~]/[!]`, `content golden score <лист>`. Порог 10%.

## Как устроена синхронизация

- Каждая запись (упражнение, тренировка, шаблон) имеет `id`, `updatedAt`, `deletedAt`, `deviceId`.
- Любая правка попадает в журнал `changes`. Клиент раз в 30 секунд, при возврате в приложение, при появлении сети
  и через 1,5 с после правки отправляет накопленное и забирает чужое одним запросом `POST /api/sync`.
- Конфликты: побеждает запись с большим `updatedAt`, при равенстве — с большим `deviceId` (одинаково на клиенте и сервере).
  Это зависит от часов устройств: держи на телефоне и ПК автоматическое время (при расхождении больше двух минут приложение предупредит).
- **Тренировки сливаются по подходам.** Клиент помнит версию, которую сервер отдал в прошлый раз (таблица `bases`), и при расхождении сравнивает с ней обе правки: изменённое с одной стороны берётся, добавленные подходы и упражнения остаются, удаление применяется, если другая сторона подход не трогала (правка важнее удаления). Если обе стороны поменяли одно и то же значение, побеждает более новая запись, а проигравшая версия попадает в «Конфликты». Поэтому перед отправкой тренировок клиент сначала забирает чужие правки. То же самое по полям делается для упражнений, шаблонов, программ, замеров тела, чек-инов и настроек игры: списки без `id` (упражнения шаблона, дни программы) сливаются по упражнению и по дню недели, а чек-ины и настройки игры сливаются и без общего предка. Целой записью по-прежнему разрешаются маршруты (`tracks`), профиль, журнал начислений игры и случай, когда запись на одной стороне удалили, а на другой правили (наша версия тогда попадает в «Конфликты»).
- **Версии.** В запросе `POST /api/sync` есть `protocol`, в ответе `protocol`, `minClientProtocol`, `schema` и `serverTime`. Несовместимость сервер сообщает кодом 426 (`server_outdated` или `client_outdated`). Старые клиенты без поля `protocol` принимаются.
- Удаление мягкое (`deletedAt`), поэтому доходит до всех устройств.
- Стартовые упражнения имеют одинаковые id на всех устройствах (`seed-001`…), дублей не будет.
- Доступ по токену устройства; токен выдаётся по одноразовому коду, на сервере хранится только хэш.

## Ограничения

- Таймер отдыха: если Android усыпит вкладку, сигнал может прийти с задержкой.
- Обновления с сервера приходят опросом раз в 30 секунд, мгновенного пуша пока нет.
- Только килограммы, только тёмная тема.
- Анимации отключаются автоматически, если в системе включено «уменьшение движения».

## Безопасность

- **Доступ.** Все данные и ассистент закрыты токеном устройства; токены хранятся на сервере только в виде хэшей. «Отключить устройство» в приложении теперь отзывает токен и на сервере.
- **Адреса (Host).** Сервер отвечает только на localhost, частные IP (LAN, Tailscale), `*.ts.net`, `*.local` и имена из `WORKOUT_ALLOWED_HOSTS` / `PUBLIC_URL`. Это защищает от DNS rebinding. Если заходишь по своему имени (например, `pc.lan`), добавь его в `WORKOUT_ALLOWED_HOSTS`, иначе будет ошибка 421.
- **CSRF и размеры.** POST/DELETE принимаются только с того же origin и с `Content-Type: application/json`; размер запросов ограничен.
- **Заголовки.** CSP, `frame-ancestors 'none'` (кнопку «Разрешить» нельзя подсунуть через iframe), `nosniff`, `no-referrer`, `no-store` для `/api`.
- **Ассистент.** Лимит 20 вопросов в минуту на устройство, не более 3 потоков одновременно, ограничен объём переписки. Данные журнала для модели помечены как недоверенные. Ключ облака не отправляется по HTTP.
- **Файлы.** `~/workout-data` и копии доступны только владельцу (700/600).
- **Не используй** `tailscale funnel` (открывает сервер всему интернету) и `--host 0.0.0.0` в недоверенных сетях: по HTTP токены идут открытым текстом.
- **Известное.** Сборочные инструменты (vite 5, esbuild) имеют уязвимости dev-сервера; сам dev-сервер больше не открывается в сеть по умолчанию (`npm run dev:lan` включает). Обновление до vite 8 ломает совместимость, его стоит делать отдельно.

## Мировой рейтинг, пауза отдыха и другое (0.5.0)
- **Рейтинги → «Весь мир»**: общая таблица по неделе, месяцу и всему времени (тоннаж, подходы, тренировки, кардио, 1ПМ по упражнению). Работает через отдельный сервис `board/` (см. `board/README.md`). Без адреса сервиса при сборке (`VITE_BOARD_URL`) раздел сообщает, что не подключён; рейтинг друзей от него не зависит.
- **Участие добровольное**, с ником вместо имени; наружу уходят только итоги за период, выход стирает всё с сервиса.
- **Честно о пределах**: подпись защищает от подмены, но не от вранья: сервис отсекает лишь невозможные цифры. Без аккаунтов и проверки данных накрутку исключить нельзя.
- **Рейтинг друзей**: метрика «Тренировки», медали, карточка «ваше место».
- **Пауза таймера отдыха**, **набор блинов в зале** для калькулятора, **пульс и зоны** (ввод вручную).
- Из списка пожеланий уже было сделано в 0.2–0.3: суперсеты, экран рекордов, прогрессия, программы, заметки к подходам, темп и сплиты, сравнение маршрутов, высота, GPX, конфликты синхронизации, выборочный экспорт, ярлыки, тема, уведомления, фото. Не сделано: фоновые push-уведомления (нужен сервер push) и считывание пульса с датчика по Bluetooth.

## Рядом и друзья (0.4.0)

Комната «Рядом» (чат и «что делает друг» во время тренировки) и рейтинги с друзьями. Подробности и решения: `ROOM_PLAN.md`, `FRIENDS_PLAN.md`.

- Нужен сигнальный релей из `relay/` (`cd relay && npm install && npm start`, настройки в `relay/README.md`) и сборка клиента с его адресом: `VITE_ROOM_RELAY_URL=wss://relay.example npm run build`. На своём сервере тот же адрес задаётся `WORKOUT_ROOM_RELAY_URL` (попадает в CSP). Для статического хостинга: `npm run build:public` пишет `dist/_headers`.
- Без адреса релея приложение работает как раньше; добавить друга можно файлом снимка.
- Друзья «на расстоянии» требуют STUN/TURN: `VITE_FRIEND_ICE_SERVERS=stun:...,turn:...`. По умолчанию связь только внутри одной сети, публичных адресов нет.
- Тесты: `npm test`, `cd relay && npm test`, `bash tests/ui/run_room.sh` (браузер, две стороны).
- Не входит: глобальный рейтинг (нужны аккаунты, сервер и модерация), push-уведомления в фоне, QR-коды.
